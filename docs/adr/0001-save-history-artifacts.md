# Store raw save observations in Git and semantic history in SQLite

We decided that the Save History Repository stores Raw Save Observations: the original `save.dat` as the canonical restore artifact, `decoded-save.json` for raw inspection and rebuilds, and observation metadata such as decoder version and timestamps. Semantic Snapshots, Semantic Events, filter results, reverse lookup indexes, and semantic Version Stamps such as `saveSchemaVersion`, optional `gameVersion`, optional `platform`, `mappingDataVersion`, `semanticCoreVersion`, and `configHash` live in a rebuildable SQLite Semantic Read Model instead of Git, because semantic mapping is expected to evolve while decoder output is comparatively stable.

This means the watcher commits stable raw observations even when the current semantic rules do not produce a meaningful event. The UI and CLI can still default to showing only meaningful semantic history, but future mapper versions can rebuild the Semantic Read Model from the fuller raw Git history instead of being constrained by old semantic filters.

Raw observation commits are controlled by a Capture Policy, including a user-configurable Minimum Commit Interval. When multiple stable save changes occur inside that interval, only the latest observation is committed, explicitly trading raw-history fidelity for lower commit frequency. The SQLite Semantic Read Model stores the complete set of derived Semantic Events; Display Semantic Event Filters are applied at query time for default history views, notifications, and meaningful-event queries, but they do not decide whether a raw observation is captured or whether a Semantic Event is retained in SQLite.
